# 카드 비교 (cpycardvs)

컴투스프로야구 V26 선수 카드를 **같은 육성 조건에 놓고 최종 능력치를 1:1로 비교**하는 웹 도구입니다.

**배포**: https://cpv-cardvs.vercel.app

> 비공식 팬 도구이며, 게임사와 관련이 없습니다.

## 왜 만들었나

같은 선수라도 카드 종류(시즌·라이브·임팩트·시그니처·골든글러브·국가대표·라이브 올스타)마다 강화·각성 한도, 훈련 레벨, 세트덱 효과가 다릅니다. 그래서 카드에 적힌 기본 능력치만으로는 "어느 카드가 실제로 더 센가"를 판단할 수 없고, 유저들은 게임 화면과 커뮤니티 표를 오가며 직접 계산해 왔습니다.

기존 사이트는 도감·덱 구성 위주라, **두세 장의 카드를 같은 조건에서 나란히 비교하는 기능**은 없었습니다. 이 도구는 그 한 가지 질문에 집중합니다.

## 주요 기능

- **1:1 비교**: 카드 2~3장의 핵심 능력치(타자 파워·정확·선구, 투수 변화·구위)를 같은 조건으로 계산해 줄마다 최고값과 차이를 보여줍니다.
- **성장 요소 반영**: 강화·각성, 훈련(재분배 확률 기준 또는 직접 입력), 특훈, 포지션 특훈, 세트덱(33단계 선택), 이달의 선수.
- **세트덱 연도 효과**: 단계마다 연도를 따로 고를 수 있어, "55점은 21년, 190점은 19년"처럼 실제 덱 구성대로 계산합니다.
- **카드별 내역**: 최종값이 어느 요소에서 얼마나 왔는지 보여줘서, 게임 화면과 대조하기 쉽습니다.
- **링크 공유**: 입력 상태가 주소(`?s=`)에 담겨, 서버 없이 링크만으로 같은 비교 화면을 열 수 있습니다.

## 설계에서 고민한 점

### 계산과 화면을 분리
게임 규칙은 모두 `lib/`의 순수 함수로 두고, `components/`는 입력과 표시만 맡습니다. 계산이 화면에 묶여 있지 않아 규칙이 바뀌어도 한 곳만 고치면 되고, 테스트도 화면 없이 할 수 있습니다.

```
기본 능력치 + 기본 보너스(+2) + 강화 + 각성 + 세트덱 + 이달의 선수 + 포지션 특훈 (lib/calc.ts)
            + 훈련 + 특훈                                                    (lib/compare.ts)
```

### 서버 없이 링크로 공유
비교 결과를 공유하려고 DB를 두는 대신, 입력 상태를 JSON → UTF-8 → base64url로 줄여 주소에 담았습니다 (`lib/share.ts`). 링크는 누구나 고칠 수 있으므로 복원할 때 모든 값의 범위를 검사하고, 하나라도 어긋나면 기본 화면으로 시작합니다.

### 값과 타입을 한 곳에서
카드 종류·스탯 목록은 `as const` 배열 하나로 두고 타입을 거기서 뽑아(`(typeof X)[number]`), 화면에 그릴 목록과 오타 검사용 타입이 어긋나지 않게 했습니다. 핵심 스탯 목록은 `satisfies`로 실제 스탯 중 하나인지 검사합니다 (`lib/types.ts`).

### 상태는 최소로, 결과는 계산으로
입력값만 state로 두고 결과는 렌더할 때마다 계산합니다. 결과를 따로 state로 두면 입력과 어긋날 수 있기 때문입니다. `useEffect`는 주소창 동기화, 통계 전송처럼 외부 시스템과 맞추는 일에만 씁니다.

## 검증

- **게임 화면 대조**: 실제 계정의 카드로 단계마다 값을 맞춰 봤습니다. 이 과정에서 모든 선수에게 붙는 **기본 보너스 +2**를 찾아냈고, 세트덱 125·160·180점 효과의 잘못된 해석을 바로잡았습니다.
- **확률 모델**: 훈련 재분배 확률은 가능한 분배를 모두 세는 모델로 계산했고, 커뮤니티에 공유된 확률표 9개를 그대로 재현하는 것을 확인한 뒤 표가 없던 카드에 썼습니다.
- **단위 테스트**: 계산·공유 링크 로직을 Vitest 테스트 124개로 확인하며 개발했습니다. 배포 저장소에는 앱 코드만 둡니다.

## 성능·접근성

Lighthouse 모바일 기준 (2026-11-13 측정):

| | 성능 | 접근성 | 권장사항 | SEO | CLS |
|---|---|---|---|---|---|
| 디자인·통계 추가 전 (배포본) | 97~100 | 100 | 100 | 100 | 0 |
| 디자인·통계 추가 후 (로컬 프로덕션 빌드) | 99 | 100 | 100 | 100 | 0 |

새 기능을 넣으면서 점수가 떨어지지 않게 한 점:
- **글꼴**: 웹 폰트 대신 기기 기본 한글 폰트를 써서 로딩이 늦어지지 않게 했습니다.
- **GA 스크립트**: 페이지가 뜬 뒤에 받아서 첫 화면을 늦추지 않습니다.
- **CLS 0 유지**: 비교 화면은 브라우저에서만 그려서, 그려질 자리를 미리 잡아 두었습니다.
- **글자 대비 기준**: 회색 바탕을 넣었을 때 보조 글자 대비가 기준(4.5:1) 아래로 떨어져서 색을 고쳤습니다.

## 지표와 실험

GA4로 다음 이벤트를 기록합니다. 측정 ID(`NEXT_PUBLIC_GA_ID`)가 없으면 통계는 꺼집니다.

| 이벤트 | 의미 |
|---|---|
| `compare_ready` | 카드 2장 이상이 핵심 스탯을 모두 채움 (실제로 비교까지 간 방문) |
| `card_add` | 세 번째 카드 추가 |
| `share_copy` | 비교 링크 복사 |
| `experiment_view` | A/B 테스트 노출 |

**A/B 테스트: 공유 버튼 문구**
- A안은 "비교 링크 복사", B안은 "이 비교 공유하기"입니다.
- 방문자를 처음 한 번 무작위로 나누고 브라우저에 기억해 둡니다 (`lib/experiment.ts`).
- 문구별 복사율(`share_copy ÷ experiment_view`)을 비교합니다.
- 현재 데이터를 모으는 중입니다.

## 프로젝트 구조

```
app/          페이지, 메타데이터, 전역 스타일
components/   입력 패널(카드·강화·훈련·특훈·포특·세트덱), 결과표, 공유 버튼
lib/          게임 규칙과 계산 (순수 함수), 공유 링크, 통계, 실험
```

## 실행

```bash
npm install
npm run dev     # http://localhost:3000
npm run build
```

통계를 켜려면 `.env.local`에 `NEXT_PUBLIC_GA_ID=G-XXXXXXX`를 넣습니다.
